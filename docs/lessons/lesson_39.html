Lesson 39: The workflow contract: one repo-owned file, from config to prompt

a repo-owned WORKFLOW.md: strict parsing, the template subset, last-known-good reload

1. Why This Feature Exists

A temporary repository owns a single WORKFLOW.md. You follow that file through every stage a host needs, in order:

1 — WRITE AND LOAD : new WorkflowPolicy({ path }) then start() resolves the YAML front matter and the prompt body into one frozen config. snapshot() is the operator view: health, watch state, prompt size, redacted provider. 2 — RENDER : renderPrompt({ issue, attempt }) fills the body from variables, createPolicyRenderer({ policy }) maps a scheduler attempt onto the template (1 → first run, N → retry N-1), an unknown variable is a PolicyError, and the parser/loader/renderer work with no policy at all. 3 — MAP : policyToSchedulerOptions({ policy }) turns the config into live scheduler options and preflight; policyToWorkspaceOptions({ policy }) yields the workspace strategy and hooks. 4 — BREAK : an edit with invalid YAML is refused. The last known good prompt still renders, and both preflight paths name the reason. 5 — RELOAD : the repaired file is applied, and a real model answers the newly rendered prompt — the prompt you saw is the prompt that ran.

Public API: WorkflowPolicy, createPolicyRenderer, parseWorkflowMarkdown, loadWorkflowFile, renderPromptTemplate, policyToSchedulerOptions, policyToWorkspaceOptions, WORKFLOW_POLICY_REASONS, PolicyError, MerciEventEmitter, EVENTS.

Run: node examples/29_workflow_contract.mjs Needs: PROVIDER + provider credentials in secret.env.
