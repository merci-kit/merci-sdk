Lesson 42: Agent definition files: one YAML, a live tool-using agent, a live subagent

*.agent.yaml definitions: load, freeze, resolve the toolset, run live, delegate live

1. Why This Feature Exists

A non-coder writes one agents/<name>.agent.yaml. This program uses that file for real — every model call below goes to the provider in secret.env:

2. What the Example Demonstrates

A — THE FILE
the YAML, on screen, plus the one script it declares. Nothing in the file builds a client, names a secret or defines a server: a definition selects what the host already provides.
B — LOAD
loadAgentFile validates every field, resolves the script on disk (contained, hashed) and returns a deep-frozen spec.
C — THE TOOLBOX
createAgentToolbox supplies a real workspace and a real host tool; resolveToolset turns use: [files], host:lookup_policy and the declared script into the exact tool list.
D — LIVE SESSION: applyAgentSpec wires a real session. The mod
LIVE SESSION: applyAgentSpec wires a real session. The model reads the note, runs the declared script tool, consults the host tool, and answers with the exact word count. The tool events below are the model's own.

LIVE PROFILE: the SAME spec becomes a subagent profile via toTaskAgent. A parent session delegates to it, and the child runs the same tools under the same approval policy.
