Lesson 35: A crash mid-run, resumed exactly once

session checkpoints, the at-most-once execution journal, the session fork

1. Why This Feature Exists

A release agent works one live deployment turn, then the process dies. The next process knows nothing except what is on disk under scratchpad/examples/20-durability/: the conversation checkpoint and the execution journal that records what already happened.

2. What the Example Demonstrates

A — the live turn
a real model calls deploy_release, a tool whose execute() appends one line to a ledger file, inside a session bound to a LocalFileSessionStore and an ExecutionJournal.
B — a tagged checkpoint
saveCheckpoint/restoreCheckpoint round-trip a payload under CHECKPOINT_KIND; asking for the wrong kind throws, so a resume cannot mistake another engine's record for its own.
C — the crash
a NEW session on the same thread id restores the transcript with loadCheckpoint(); the deploy is re-issued at its recorded boundary with the restored journal and REPLAYS — the ledger keeps exactly one line.
D — interrupted work
a row left in JOURNAL_STATUS.INTENT (the process died mid-call) fails closed for a non-idempotent tool; only a tool that declares idempotent: true is re-run.
E — the fork
forkCheckpoint branches the thread; the branch takes its own turn and the source history does not move. What this shows: - at-most-once side effects across a process restart - withSessionStore + withExecutionJournal on one session - toolJournalKey as the identity a replay is matched on - forkCheckpoint as the branch point for a second attempt Run: node examples/20_durability.mjs Needs: PROVIDER + provider credentials in secret.env. @version 0.25.0

/**
 * A deployment step whose execute() performs a REAL side effect: one appended
 * line in the ledger file. Any re-run is therefore visible on disk.
 * @param {{ledgerPath: string, counter: {n: number}, idempotent?: boolean}} arg0
 */
function deployTool({ ledgerPath, counter, idempotent = false }) {
    return {
        name: 'deploy_release',
        description: 'Deploys the current release to one environment and appends the deployment to the ledger file. Performs a real side effect.',
        parameters: {
            type: 'object',
            properties: { environment: { type: 'string', description: 'Target environment, e.g. staging.' } },
            required: ['environment'],
        },
        idempotent,
        /** @param {{args?: {environment?: string}}} arg0 */
        execute: async ({ args = {} }) => {
            const environment = String(args.environment ?? 'staging');
            counter.n += 1;
            const deployment = `dep-${counter.n}`;
            await appendFile(ledgerPath, `${JSON.stringify({ deployment, environment, at: new Date().toISOString() })}\n`, 'utf8');
